what it actually does
01

ground

point it at a domain. everything it ingests is normalized into a finding — titled, categorized, confidence-scored, and stamped with the urls it came from. nodes and edges never hold raw text; they reference finding ids.

github.com ↗ vision.md ↗
02

grow

when a query bands sparse or gap, the explore pipeline plans sub-queries, fans out searches, crawls the best hits, extracts candidate findings, and merges them through dedup. progress streams as it runs.

03

answer

a read assembles a preamble: the findings that matter for this query, ordered by similarity and confidence, graded with a coverage verdict. that block is what your agent consumes.

faq
is this just a vector database? {{ g0 }}

no. embeddings are only the retrieval layer. the unit of storage is a finding — text plus category, confidence, and provenance — and a typed graph of concepts, technologies, people, and companies sits over the top of it.
self-hosted or hosted? {{ g1 }}

both. sqlite + sqlite-vec gives a zero-infra local kb on one file. point it at supabase + pgvector when the kb needs to be shared. same engine, same api.
how are stale facts corrected? {{ g2 }}

re-ground the topic. the explore pipeline merges new findings against the old ones instead of overwriting, so the correction and what it replaced both stay inspectable.
which models does it need? {{ g3 }}

an embedding model for retrieval and an llm for extraction. both are configurable; the engine is not tied to one provider.
how do i plug it into my agent? {{ g4 }}

mcp. the engine ships an mcp server — tap a kb for a preamble, or trigger explore when coverage comes back gap. there is an http api underneath if you prefer it.
license and pricing {{ g5 }}

the engine is mit and self-hostable, forever. the hosted control panel is in private beta — pricing lands with it.
